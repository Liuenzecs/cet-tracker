# CET Tracker — 词汇 Markdown 格式说明

## 本地解析器支持的格式 (v0.2.0)

本地解析器基于正则表达式和关键词识别，支持以下多种格式。解析器不会抛出异常——未识别的内容会清洗后放入 `meanings_json` 字段。

### 格式 A：冒号型字段

```
# pending

释义：等待处理的；悬而未决的
常见用法：
- pending decision
- pending approval
```

### 格式 B：标题 + 子章节

```
## pending

### 释义
- 等待处理的
- 悬而未决的

### 例句
- The case is still pending. — 案件仍在审理中。
```

### 格式 C：纯文本 + 冒号字段

```
pending
释义：等待处理的；悬而未决的
例句：
The case is still pending. — 案件仍在审理中。
```

### 格式 D：Markdown 表格

```
| 单词 | 释义 | 例句 |
| pending | 待处理的 | The case is still pending. |
```

### 格式 E：混合格式

解析器尽力处理包含加粗、编号、表格、分隔线、中英文混合等格式的内容。

## Markdown 噪声自动清洗

v0.2.0 新增文本清洗能力，解析时自动去除：

- `**加粗**`、`*斜体*`、`` `代码` `` 外层符号（保留内容）
- Markdown 表格分隔行 `|---|---|---|`
- 开头 `#`、`##`、`###` 标题符号
- 纯分隔符 `---`、`***`、`___`
- 空字符串和纯噪声行

## 支持的关键词

| 字段 | 识别关键词 |
|------|-----------|
| 释义 | 释义、含义、意思、定义、meaning |
| 常见用法 | 常见用法、用法、搭配、常见搭配、usage |
| 例句 | 例句、示例、例子、example |
| 易错点 | 易错点、注意点、注意事项、易错、注意、mistake |
| 同义替换 | 同义替换、近义词、同义词、替换、synonym |
| 易混词对比 | 易混词对比、近义词对比、对比、比较、易混、comparison |
| 写作可用句 | 写作可用句、写作句、写作、六级写作、writing |

## 解析行为

1. **始终成功**：即使格式无法识别，解析器也不会抛出异常。
2. **噪声清洗**：所有 Markdown 格式符号在输出前被清洗。
3. **文档标题过滤**：包含"图片笔记"、"词汇表"、"目录"、"复习表"等关键词的行不会被识别为词条。
4. **每个词条至少一个 term**：无法提取 term 时，使用 `未分类条目` 作为兜底。
5. **raw_markdown 保留**：原始 Markdown 始终保留在数据库中，可随时用改进后的解析器重新解析。

## AI 规范化（可选）

可通过配置后端 `.env` 文件启用 AI 辅助规范化：

```env
AI_NORMALIZER_ENABLED=true
AI_API_KEY=your_api_key
AI_BASE_URL=https://api.deepseek.com
AI_MODEL=deepseek-chat
AI_TIMEOUT_SECONDS=30
```

AI 规范化功能特点：
- 仅格式规范化，不扩写原文没有的内容
- 输出严格 JSON，经 Pydantic schema 校验后返回
- 失败时自动回退到本地解析器
- 用户在导入页可以看到预览后再保存
- API Key 只存放在后端 `.env`，前端不可见
- AI 规范化未启用时，本地解析器照常工作

## 内容合规

- 本项目不内置、不提供、不分发任何 CET 真题内容
- 用户应确保导入的 Markdown 内容来源合法
- 演示数据 `scripts/seed_demo.py` 中的词汇均为虚构
